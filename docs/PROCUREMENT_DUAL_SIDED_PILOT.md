# Dual-sided procurement pilot

## Purpose

Stödassistenten should be able to help a small Swedish company move from "public procurement feels like an ocean" to a structured, truthful next action, while also being credible to a procurement professional on the buyer side.

This pilot therefore evaluates the same product from two deliberately separated perspectives:

1. **Supplier-side user** — a small company seeking relevant public procurement opportunities and help understanding requirements, qualification, documents, deadlines and submission readiness.
2. **Buyer-side domain reviewer** — a public procurement professional who pressure-tests whether the product explains the process correctly, avoids misleading claims, distinguishes mandatory requirements from guidance and supports fair, auditable public procurement.

The two roles must never be used to influence a live procurement or give one supplier privileged information.

## Core user journey — supplier side

A business owner should be able to say in ordinary language:

> "Jag har ett städbolag och vill börja lämna anbud till kommuner men jag vet inte var jag ska börja."

The product should then progressively structure only the facts that materially change the answer, for example:

- company type and services,
- geography / willingness to deliver,
- approximate capacity,
- relevant references or experience,
- certifications or quality/environmental processes where relevant,
- staffing and subcontractor model,
- insurance and financial/administrative readiness,
- whether the user wants current opportunities, learning, a bid-readiness check or help with a specific published procurement.

The product should then support a flow such as:

`understand business → identify relevant opportunity categories → find/publicly verify opportunities → explain mandatory vs optional requirements → identify gaps → build document checklist → create bid-readiness plan → prepare structured draft answers → final user review → handoff to official procurement system`

No submission should be represented as complete or compliant unless the actual procurement documents and all mandatory requirements have been checked.

## Buyer-side review

The procurement professional is not a source of privileged facts for the supplier. The reviewer should instead test the product using public or synthetic procurement material and assess questions such as:

- Does the product distinguish exclusion grounds, qualification requirements, mandatory requirements, award criteria and contractual terms?
- Does it understand when a requirement is procurement-specific rather than a general rule?
- Does it avoid promising that a supplier "will win" or "is approved"?
- Does it clearly identify when the official procurement notice/document must control?
- Does it help a small supplier understand what is missing without rewriting the buyer's requirement into something easier?
- Does it avoid discriminatory or competition-distorting guidance?
- Can it explain a rejection/qualification issue in plain language while staying faithful to the published material?
- Can an auditor or municipal employee see the source and reasoning trail?

## Independence and conflict safeguards

For pilots involving relatives, friends or people active in procurement:

- use public, historical or fully synthetic procurement examples by default;
- do not use confidential, unpublished, commercially sensitive or security-classified information;
- do not ask a public employee to reveal planned requirements, competing bids, scoring, internal deliberations or future procurement strategy;
- do not test a supplier against a live procurement in which the buyer-side reviewer is personally involved;
- keep supplier-side feedback and buyer-side review separate until the test case is closed;
- document all factual corrections as source-verifiable product learning, not as insider knowledge;
- never optimize the product to favor a named supplier, municipality or relationship.

## What we want to learn

### Supplier outcome

- Could the user understand where to start without prior procurement expertise?
- Did the product identify a genuinely relevant public opportunity or clearly explain why none was suitable?
- Did the user understand mandatory requirements and missing evidence?
- Was the next action obvious?
- Did the product reduce perceived complexity and document burden?
- Would the user return for the next opportunity?

### Buyer/reviewer outcome

- Were process explanations accurate?
- Were requirements represented faithfully?
- Were uncertainty and source boundaries clear?
- Did any recommendation risk giving false confidence or unfair advantage?
- Would the reviewer be comfortable recommending the tool as a general learning/readiness aid if later independently validated?

## Permanent learning loop

Each verified miss should become one or more of:

- synthetic regression case,
- benchmark case,
- source/data correction,
- question-order improvement,
- new procurement concept/ontology entry,
- document-readiness rule,
- UX clarification,
- red-team guardrail.

Supplier feedback alone must not change procurement truth. Buyer feedback alone must not become a hidden rule. Changes affecting factual procurement requirements must be grounded in current public sources and, where procurement-specific, the actual published procurement documents.

## Product capabilities this pilot should eventually exercise

- situation-first SME interview,
- procurement opportunity discovery,
- CPV/category assistance without requiring the user to know CPV terminology,
- qualification/readiness check,
- document checklist,
- requirement extraction from procurement documents,
- mandatory/optional/award-criteria separation,
- deadline and clarification-question reminders,
- bid draft assistance,
- no-bid / bid recommendation with explainable reasons,
- submission handoff to the official procurement channel,
- post-result explanation and learning,
- watchlist for future relevant opportunities.

## Non-goals for the first pilot

The first pilot does not:

- submit a real bid automatically,
- guarantee eligibility or award,
- replace legal/procurement advice,
- use confidential buyer information,
- connect to a municipality's internal procurement systems,
- make autonomous commercial decisions for the company.

## Strategic test

The supplier-side user should finish thinking:

> "Nu förstår jag vad jag behöver göra för att kunna lämna ett seriöst anbud."

The buyer-side reviewer should finish thinking:

> "Den här tjänsten hjälper leverantören att förstå den offentliga processen utan att förvanska kraven eller ge falsk trygghet."

When both statements are supported by actual pilot evidence, Stödassistenten has a strong foundation for a broader SME/public-procurement track.

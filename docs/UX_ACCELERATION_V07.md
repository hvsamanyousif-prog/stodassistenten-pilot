# UX acceleration v0.7

Goal: move the public pilot from target-group cards and scripted funnels toward a professional situation-first assistant.

Product rule:
- The user starts with the problem, not a benefit name.
- The interface interprets the wording and offers the most plausible next paths.
- Concrete needs should reach a useful action in one or two decisions, not a generic five-step interview.
- Accessibility is part of the main interaction model, not a separate accessibility mode.
- The public browser prototype may use transparent local heuristics for intent routing; it must not pretend that this is the final private AI matcher.
- Truth claims remain source-first and conservative.

Current v0.7 focus:
1. Professional shared shell with a situation composer as the primary CTA.
2. Local situation-router prototype for dental, vision, work/sickness, economy, studies, company/procurement, association and broad/unknown cases.
3. Dental guidance based on the need the user expresses: pain/care, cost/support, or uncertainty.
4. Vision guidance based on the activity that is blocked: home, reading/technology, work/school, or broad guidance.
5. One product and one shared visual language across all entries.
